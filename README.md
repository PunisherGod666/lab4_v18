# Лабораторна 4, варіант 18

m = 2 поля. Частоти операцій: поле 0 — read 20%, write 10%; поле 1 — read 25%, write 10%; string 35%.

## Схема захисту даних

Два `std::shared_mutex`, по одному на кожне поле (`include/fields.h`):

| операція | що блокується |
|---|---|
| `read i` | `shared_lock` на м'ютекс поля i |
| `write i` | `unique_lock` на м'ютекс поля i |
| `string` | `shared_lock` на обидва м'ютекси (завжди в порядку 0, 1); значення копіюються, рядок форматується вже без блокування |

Чому так:
- 80% операцій лише читають (20 + 25 + 35), тому shared-блокування дозволяють їм іти паралельно.
- Окремий м'ютекс на поле: запис у поле 0 не зупиняє роботу з полем 1 і навпаки.
- `string` бере обидва м'ютекси, щоб отримати узгоджений знімок обох полів. Найдорожча частина (форматування) виконується після звільнення м'ютексів.
- Кожне поле з м'ютексом вирівняне на 64 байти (окрема кеш-лінія) — немає false sharing між полями.
- Взаємоблокування неможливе: два м'ютекси одночасно бере тільки `string` і завжди в однаковому порядку.
- Атомарні змінні не використовуються; потоки стартують за сигналом через `mutex` + `condition_variable`.

## Тестові файли

`generator.exe` створює `data/<a|b|c>/threads<k>_<i>.txt` — для k = 1, 2, 3 потоків по 300000 / k операцій у файлі кожного потоку (разом завжди 300000). Частки операцій у кожному файлі точні, порядок випадковий (фіксований seed).

- **a)** частоти за умовою: 20 / 10 / 25 / 10 / 35
- **b)** усі частоти рівні: 20 / 20 / 20 / 20 / 20
- **c)** дуже не відповідають умові (переважають записи): 5 / 40 / 5 / 40 / 10

(порядок: read 0, write 0, read 1, write 1, string)

## Результати (Release, середнє з 10 запусків, мс)

| файл | 1 потік | 2 потоки | 3 потоки |
|---|---|---|---|
| a) | 23.450 | 26.465 | 34.525 |
| b) | 17.485 | 20.656 | 27.969 |
| c) | 10.387 | 23.986 | 26.517 |

Повний вихід — `results/results.txt`.

Операції дуже короткі, тож у кількох потоках виграшу немає: потоки змагаються за кеш-лінії м'ютексів. Але у файлі a), під який оптимізовано структуру, перехід з 1 до 2 потоків коштує лише +13%. У файлі c), де переважають записи (виключні блокування), той самий перехід — +130%. Абсолютний час a) більший, бо там 35% `string` — найдорожча операція.
